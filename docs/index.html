Call Checker

A Windows desktop tool for finding callsigns in a local SQLite database, inspecting candidate source databases, and importing callsigns you select.

This site documents the source project. No downloadable application package is currently provided.

Callsign lookup

Call Checker searches a local table named callsigns with a callsign text column. It conservatively matches portable callsigns while retaining the full entered call for copying. Verify results against an authoritative source; this tool is not a substitute for official callsign information.

Run from source

Use 64-bit Windows with Python 3.14 and Tkinter. Clone or download the source repository, then run these commands from its root in PowerShell:

py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r Build\requirements.txt
.\.venv\Scripts\python.exe .\CALL_Checker.py

The export includes a minimal starter database containing only the author's seed callsign, PA1RGX. To add other callsigns, configure source files deliberately and use the application's import feature.

See the repository's README for complete setup, build and test instructions.

Scan and import sources

Scanning lists candidate file paths under roots you configure; it does not read database contents. Inspect source schemas read-only, select source tables explicitly, and review the choices before importing. Imports append selected callsigns to the target database, committing each completed source separately. Keep a separate backup before an import.

Read the source and import help before scanning or importing. Access .mdb support has additional Windows provider requirements.

Data, privacy and limitations

  • No populated operator database or bulk callsign list is included. The published starter contains only PA1RGX.
  • Only scan roots and source files you intend to use. Review paths and source data before importing.
  • Source datasets may have separate licensing or redistribution terms. Review those terms before using or sharing a dataset.
  • The scan-root restriction is an application guard, not an operating-system security boundary.

The application is Windows-only and its graphical interface uses Tkinter. Access database support depends on compatible installed 32-bit components.
